{% load icons %}{% comment %} The Compare page's filters (quick task 261103-lfm, D-2). Parameters: form (the bound CompareForm), chips (pk, name, status, checked per location, list order), ranges (value, label, checked, index), from_value and to_value (the effective period on a valid page, the submitted text on an invalid one), earliest and today (the date inputs' bounds) and summary (the one line under the form; only on a valid page). - One GET search form (role=search, no CSRF token: a token in a URL would leak, R-1) to /compare/, so a comparison is a bookmarkable link and the page needs no JS. novalidate: the server validates, so the date inputs' min/max never block switching to a preset. The form does not carry the timeline's tl, so a new comparison resets its window. - The error summary first when the form is invalid (its links go to #id_loc, #id_range, #id_from and #id_to). - The hidden empty loc sentinel, so a submit with every chip unchecked reads as "none" (an error), not as "no loc in the URL" (every location). - fieldset#id_loc: one chip per location, a label wrapping its checkbox, the status LED (aria-hidden, styled from the label's data-status exactly like the sidebar's: on, off, maintenance hatch, waiting ring) and the name. 44 px tall, 32 px on a fine pointer from md. - fieldset#id_range: the period radios (7, 14, 30, 90 days, Custom). - The From and To date inputs, always shown and prefilled (with the preset's dates for a preset); they apply to Custom only. - The Compare button and the Reset link (back to every location over 7 days). - Field errors at id__error, wired by aria-describedby and aria-invalid. Every class is spelled out; no class name is built from data. {% endcomment %}
