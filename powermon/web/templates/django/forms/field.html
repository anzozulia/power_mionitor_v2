{% load icons forms_ui %}{% comment %} Field group (06-UI-SPEC Components > Form field; UI-01, UI-12, R1, R3). The TemplatesSetting renderer uses it for {{ field.as_field_group }}; a page can also include it with field=form.x. Its only context is field (the BoundField); the form is field.form. In this order: the label (for= the control's id), the control (the widget template), the first error at id__error, the re-paste note at id__note (the bot token only, and only while form.show_token_note is true), the help at id__helptext. - The control's aria-describedby and aria-invalid come from Django's BoundField wiring, unchanged (LocationBoundField adds the note id), so they name exactly the ids above. - The help text is printed as {{ field.help_text }}, never with the safe filter: plain strings are escaped, and the edit form's token help is already a format_html string. - The note is the form's own copy (form.token_note), never a template literal. Optional include parameters (06-17; with none of them the group renders exactly as above): - suffix: the add-on text after the control, e.g. "s" for the seconds fields. It is aria-hidden: the label already names the unit. - leading_icon: the name of an icon drawn inside the control at its left edge, e.g. key-round for the bot token; the control gets the room for it. - control: the kind of extra control attributes (forms_ui CONTROL_ATTRS): "seconds" adds inputmode numeric, "secret" adds the password-manager ignore hints. The control is still Django's widget render with Django's own attributes. - help_in_details: the summary text of a details disclosure the help moves into (the chat ID's long help). The help keeps its id inside the disclosure, so aria-describedby still resolves; help_testid is the disclosure's data-testid. The add-on and the icon sit in one row with the control; the row's arbitrary variants square the control's right corners next to the add-on and widen its left padding for the icon. {% endcomment %}
