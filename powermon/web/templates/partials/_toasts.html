{% load icons %}{% comment %} Toast live regions (06-UI-SPEC Layout Shell > Toasts, Components > Toast; UI-09, UI-12). Included by the app layout as {% include "partials/_toasts.html" %} and by the auth layout with auth=True, which places the phone stack 16 px from the top (that layout has no top bar). Never included by the error layout, which reads no context variable (R11). The partial reads only messages (Django's messages context processor). - Both regions are always rendered, also when empty: error messages go to the alert region (role=alert, assertive), success, info and warning messages to the status region (role=status, polite). Each region loops over messages and keeps its own levels; a level without a tone of its own (a custom level) renders as info. - Every message renders server-side as a toast, so toasts work without JavaScript. The toasts component in admin.js (bound on each region) reveals the Dismiss buttons, re-announces each toast's text after load, removes a success toast when its timer bar ends and moves the focus to main when a focused toast closes. - Each toast: data-level (the Django level tag), the 20 px tone icon, the visually hidden "Warning: " / "Error: " prefix before toast-text, data-sticky when the message's extra tags hold "sticky", the 10 s timer bar only on a success that is not sticky (paused on hover and focus), and the Dismiss button (JS only, rendered hidden). - DOM order is arrival order. Phones: full width under the top bar, the alert region first and the newest toast on top. From sm: a 384 px column 16 px from the right and bottom edges, the alert region below the status region and the newest toast nearest the corner. - Tone classes are spelled out per level, never built from a variable, so the Tailwind scan finds them. Only the timer bar has a clipping wrapper, so focus rings are never clipped. {% endcomment %}
